# Security Policy

Security fixes are applied to `main` and the current production release.

Do not disclose suspected vulnerabilities in public issues. Report them privately through the repository's configured GitHub security reporting channel.

Include the affected component, reproduction steps, expected versus observed behavior, security impact, and sanitized evidence. Never include passwords, API keys, private keys, access tokens, or other credentials.

SPR's verification standard is evidence-first: missing or unavailable evidence must not be represented as verified. Production readiness requires the repository hardening and release gates to pass; source inspection alone is not proof of external infrastructure health.
